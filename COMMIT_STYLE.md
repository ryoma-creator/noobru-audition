# Git Commit Message Style Guide

## Principle
**Conventional Commits are optional / not required.**

This project prioritizes human-readable, immediately clear English.

## Template
- Short
- Just what was done
- Not overly formal

## Good Examples (Initial Setup)

- `init repo structure and docs`
- `add pricing script documentation`
- `add base HTML/CSS/JS files`

## Good Examples (During Implementation)

- `build pricing section markup`
- `style pricing cards and guarantee`
- `add reviews section layout`
- `integrate price exchange script`
- `optimize layout for mobile and desktop`
- `pagespeed tweaks`

## Avoid

- `feat: ...` / `chore: ...` (Not bad, but in this company's context it feels "AI-like/too formal")

👉 If you've been using `feat:` in the past, it's OK to switch mid-project.
